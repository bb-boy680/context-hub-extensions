# DeepSeek Harness integration

Context Hub asset integration for [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness), based on the default file protocol of release `0.2.1-rc.5`. This integration is not published or endorsed by DeepSeek.

This extension delivers directory-form skills to `.dsh/skills/<name>/SKILL.md` in the selected workspace and `~/.dsh/skills/<name>/SKILL.md`. The Hub's shared workspace `.agents/skills` is also available. Select the repository root as the workspace: DSH discovers the nearest Git root, while the Hub writes to the selected workspace. Flat skill files, global `~/.agents/skills`, and custom `DSH_HOME` or `DSH_AGENTS_HOME` roots for skills are not managed by this integration.

For prompts, the extension manages marked sections in `~/.dsh/AGENTS.md`. The Hub's shared workspace `AGENTS.md` action remains available. Other instruction files, including `~/.agents/AGENTS.md`, local files and nested `CLAUDE.md`, are not managed here. Custom `DSH_HOME` is not applied to the global instructions path.

MCP servers are installed in `<DSH_HOME>/cordis.patch.yml` (`~/.dsh/cordis.patch.yml` by default). The extension also scans initialized profiles under `<DSH_HOME>/profiles/<name>/cordis.patch.yml`; existing safe declarations may be changed at their own location. It supports stdio and Streamable HTTP; SSE is refused. Expressions, aliases, ambiguous entries and unsafe edits are left unchanged. The displayed switch describes the file declaration, not the final composed profile or a successful connection. Reloading or restarting DSH may be needed to apply changes. Explicit `--patch` layers and bundle-provided servers are outside the scan.

MCP requires the Context Hub file-root, guarded-write, dynamic-place and YAML APIs introduced alongside this integration; the current engines range is a development baseline and must be updated to the first released host version containing those APIs before publication. Native DSH bundle packages are recognised when their `package.json` declares `dsh.bundle.patch`, and the Plugins page lists each initialised profile's selected bundles and local package metadata as read-only entries. This extension does not install, enable, disable or remove bundles: those actions are refused, and no profile manifest, dependency or lockfile is written. Dynamic profile destinations, scoped native library names and the npm dependency/lockfile write protocol remain required before a writable bundle installer can be registered.
